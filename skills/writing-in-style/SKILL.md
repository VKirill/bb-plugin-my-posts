# writing-in-style, писать по профилю

Профиль — не украшение, а спецификация: слой C (`do`, `avoid`, шаблон) управляет письмом,
слой A (числа) проверяет результат машинно. Устройство слоёв описано в навыке
`style-portrait`, файл `layers.md`.

## Сначала найди профиль

```bash
ls *-style.md *-metrics.json profiles/ 2>/dev/null
```

Профиля нет — не выдумывай голос по паре примеров: скажи об этом и предложи снять его
навыком `style-portrait`. Есть только `<who>-style.md` без метрик — писать можно, но
машинная сверка не отработает, предупреди и держись числовых ориентиров из профиля.

## Порядок

1. **Раздели факты и форму.** Выпиши, что должно быть сказано: тезисы, цифры, ссылки,
   вывод. Стиль меняет форму; факт, которого нет во входных данных, не появляется.
2. **Возьми шаблон из слоя C** и разложи фактуру по его блокам. Шаблон задаёт порядок,
   а не количество: лишние блоки выбрасываются, новые не придумываются.
3. **Пиши по `do`.** Числовые ориентиры держи в голове с самого начала — переписывать
   длинные периоды в короткие фразы потом дороже, чем сразу писать короткими.
4. **Вычитай по `avoid`.** Каждый пункт — отдельный проход, а не общее впечатление.
5. **Проверь машинно.** Скрипт лежит в соседнем навыке `style-portrait`; навыки ставятся
   одним плагином, поэтому скрипт доступен по общему пути установки:
   ```bash
   # W — абсолютный путь папки этого SKILL.md (зависит от машины: возьми из пути, по которому ты прочитал этот файл)
   python3 "$W/../style-portrait/style.py" check who-metrics.json draft.md
   ```
   Сверка идёт с диапазоном автора (p10–p90), а не со средним, поэтому «в диапазоне»
   означает попадание в его естественный разброс. Строки `!! … — чего в профиле нет`
   разбирай первыми: это чужие признаки, а не оттенок. Затем «за край» с крупными
   процентами. Правь текст, а не пороги. Скрипт недоступен (`style-portrait` не установлен
   рядом) — сверяйся с разделом «числовые ориентиры» профиля вручную и скажи пользователю,
   что машинной проверки не было.
6. **Финальный аудит машинных следов** — гуманайзером **в режиме диагностики, без
   переписывания** (для русского, например, `humanizer-ru`). Применяй из его находок только
   то, что не спорит с профилем: где общее правило («длинное тире — хард-бан», «эмодзи —
   декор», «списки — листикл») противоречит замеренной черте автора, **главнее профиль**.
   Живой авторский текст спокойно получает у такого сканера «чисто» и всё равно ловит
   хард-бан на тире — это цена универсальных правил, а не дефект текста.
7. **Перепроверь сверку** после правок и покажи итог.

## Порядок проходов

Текст писала модель с нуля: сперва гуманайзер полным редактированием (снять слоп с сырья),
потом этот навык, потом сверка, и в конце аудит без правки. Последний проход выигрывает
форму, поэтому голос надевается после вычистки, а не до: пущенный после стиля гуманайзер
срежет авторские черты, приняв их за маркеры. Текст изначально авторский — первый шаг
пропускается.

## Чего делать нельзя

| Соблазн | Почему нет |
|---|---|
| Взять из корпуса шутку, пример или прозвище | Переносится приём, а не наполнение: чужая конкретика читается как плагиат |
| Подогнать текст под числа, ломая смысл | Метрики — сигнал, а не цель; сначала мысль, потом форма |
| Игнорировать раздел «утечка содержания» | Там перечислено, что держится на теме корпуса и переносу не подлежит |
| Писать по профилю чужого автора от своего имени | Копия чужой манеры читается как пародия, а иногда и как подлог |
| Считать сверку пройденной при коротком тексте | Меньше ~120 слов: доли шумят, смотри только грубые расхождения |

## Если правится готовый текст

Факты, цифры, ссылки и порядок мыслей остаются как есть. Меняются: длины фраз и абзацев,
связки, пунктуация, разметка, обращения к читателю, начало и концовка. Показывай результат
целиком, а не диффом по предложениям: стиль виден только на целом тексте.
